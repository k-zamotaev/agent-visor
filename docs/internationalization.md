# Русский и английский

## Поведение

- Селектор RU/EN доступен в верхней панели на всех страницах.
- Форма сетевого доступа и окно входа также доступны на двух языках.
  Для сообщений скрипта запуска используется `launch.py --language en`.
  Служебные сообщения Uvicorn сохраняют стандартный английский текст.
- Язык сохраняется в localStorage только этого браузера, ключ agentvisor-language.
  По умолчанию используется русский. На сервере нет общего переключателя языка.
- Переключение не очищает введённые поля, выбранные флажки и раскрытые настройки.
- Новая задача фиксирует `language: ru | en`; старые задачи без этого поля остаются русскими.
- Во время просмотра системные сообщения переводятся в язык интерфейса.
  Исходное сообщение и время события остаются в базе; история не мигрирует и не перезаписывается.
- Произвольные ответы модели, reasoning, stdout/stderr, названия инструментов,
  содержимое документов, цели, имена задач, пути и модели сохраняются без перевода.
- Реальный агент получает инструкцию писать пояснения на языке задачи.
  Это инструкция модели, а не автоматический перевод её вывода.
- Демонстрационный агент формирует сообщения и документы на языке запуска.

## API и хранение

Язык ответа выбирается через `Accept-Language`; поддерживаются ru/en, региональные
варианты и веса q. Неподдерживаемый или отсутствующий язык даёт русский.
В ответе API присутствуют Content-Language и Vary: Accept-Language.
При создании задачи явное поле language имеет приоритет над заголовком.

Для системных событий Store сохраняет исходный шаблон сообщения в data._i18n
и текст на языке задачи в message. При выдаче API служебное поле убирается
из data, а оригинальная запись доступна в message_original. Существующие события
без метаданных переводятся по тем же шаблонам. Внутренние kind/status не переводятся:
это стабильные идентификаторы для программной обработки.

Причина остановки хранит reason_source, чтобы язык просмотра не изменял состояние
supervisor. Ошибки внешнего runtime сохраняют исходные подробности;
переводится только известная оболочка сообщения AgentVisor.

## Каталог и интерфейс

Общий словарь — agentvisor/static/locales/en.json. Русские исходные сообщения
используются как ключи. Подстановки обозначены {0}, {1} и далее; их набор должен
совпадать в обоих языках. Python использует точные сообщения и шаблоны.

JavaScript использует txt для точных сообщений, tr для шаблонов и markup для
статических HTML-фрагментов. Переводятся только литералы программы. Значения,
вставленные через интерполяцию, не проходят поиск и замену, поэтому имя проекта
«Модель» не превращается в «Model». Статический HTML собирается один раз до
загрузки пользовательских данных; общий MutationObserver для перевода не применяется.

После смены языка обновляются lang документа, aria-label, placeholder, заголовки,
форматирование чисел и времени. Старый ответ фонового опроса не заменяет данные,
которые уже запрошены на новом языке. Каталог входит в fingerprint сборки.

## Проверки

`tests/test_i18n.py` проверяет язык API, старые журналы, язык новых событий,
подстановки, сохранность исходных ответов и английскую демонстрацию.
`tests/test_frontend_i18n.mjs` проверяет переключение, метрики, статусы и
сохранение произвольного текста. Команды запуска — в [testing.md](testing.md).

При изменении интерфейса также проверяйте RU → EN → RU на пяти страницах,
сохранение заполненной формы и языка после перезагрузки, длинные подписи
на узком экране. Следование реальной модели языковой инструкции проверяется
отдельным интеграционным прогоном.
