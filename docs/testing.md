# Проверки AgentVisor

Команды выполняются из корня репозитория. Для автоматических тестов модель
не нужна: процессы агента и ответы модельных серверов имитируются.

## Python и JavaScript

Используйте Python из виртуального окружения проекта и установленный Node.js:

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
node tests/test_frontend_i18n.mjs
```

Python-тесты проверяют цикл задач, остановку дерева процессов, паузу и продолжение,
таймауты, пределы повторов, отсутствие прогресса, смену цели, устаревший DONE,
независимую проверку результата, защиту API и адаптеры моделей.
Проверки восстановления различают отказ модели и ошибки команд: исправный runtime
не перезагружается из-за зависшего инструмента, а следующая сессия получает
фактический вывод неудачной проверки. Проверяются сохранность памяти ошибок,
предотвращение слепых повторов и постоянное положение дополнений рядом с целью.
Тесты управления командами охватывают опрос, независимый таймаут, ограничение вывода,
лимиты процессов и очистку дерева при отмене/закрытии сессии.
Политика команд проверяется отдельно: наследование общих/проектных и агентских
запретов, команды после `;`/перевода строки, quoted-вызов Git, динамические имена
и аргументы, отключение native-транспорта при `external_directory=deny` (включая
внешний путь в аргументе из рабочего каталога проекта) и отказ без утечки
конфигурации при ошибке CLI.
На Windows тесты используют настоящий AST-парсер PowerShell, не выполняя
проверяемые запрещённые команды.
Проверки локализации охватывают язык API, события, подстановки и сохранность
произвольного пользовательского текста.

Тесты запуска проверяют файловую блокировку между процессами, понятное сообщение
при занятом каталоге и повторное открытие прежнего экземпляра после обновления
исходников. Отдельный HTTP-прогон меняет 127.0.0.1 → 0.0.0.0 → 127.0.0.1 через
API с реальными перезапусками и проверяет сохранность задачи и кода доступа.
Проверки сети охватывают вход/выход, Origin, CSRF, поддельный X-Forwarded-For,
неверный Host и запрет перезапуска при активной задаче или операции с моделью.

Проверки LM Studio охватывают установку при отсутствии CLI, подготовку daemon/API,
ожидание готовности, отмену, ошибки доступа, повторное использование приложения,
сохранение дочернего сервиса после выхода CLI, защиту чужих экземпляров и
сохранение состояния скачивания. Инсталлятор и ответы сервиса в этих тестах
имитируются; реальная установка проверяется отдельно.

## Linux в Docker

```sh
docker build -t agentvisor:local .
docker run --rm agentvisor:local python -m tests.smoke_container
docker run --rm agentvisor:local sh -c "pip install --user -r requirements-dev.txt && python -m pytest -q -p no:cacheprovider && node tests/test_frontend_i18n.mjs"
```

HTTP-проверка запускает приложение и демонстрационного агента, проверяет создание
задачи, четыре итерации, чек-лист, журнал и защиту API. Контейнер удаляется после
выполнения; модель не загружается.

Для реальной проверки установки и управления `llmster` используйте отдельный
одноразовый контейнер, без томов с рабочими моделями и задачами:

```sh
docker run --rm --init agentvisor:local python -m tests.smoke_lmstudio
```

Этот тест скачивает официальный headless-runtime и небольшую SmolLM2 135M
Q4_K_M (около 105 МБ весов). Нужны Интернет и несколько гигабайт свободного
места для runtime. Проверяются установка с нуля, daemon/API, скачивание с
прогрессом, загрузка, реальная генерация, выгрузка, восстановление после
завершения daemon и остановка сервиса. Тестовая модель служит проверке
инфраструктуры; она не заменяет проверку OpenCode с моделью для инструментов.
Загрузка также сверяет применённые Flash Attention и Q8 K/V через SDK.

## Реальная модель

Для отдельного интеграционного прогона нужны установленный OpenCode
и скачанная модель с поддержкой инструментов. Локальный LM Studio при
необходимости запускается автоматически:

```sh
python -m tests.smoke_model --model <идентификатор-модели>
```

Для Ollama добавьте `--runtime ollama --url http://127.0.0.1:11434`.
Тест создаёт отдельный каталог в `.agentvisor-data/`, запускает OpenCode с
разрешёнными инструментами и проверяет точное содержимое созданного файла.
В `result.json` сохраняются результат и события. Такой прогон использует
ресурсы модельного сервера и может загрузить или перезагрузить модель.

Для проверки автоматического подбора добавьте `--auto-profile`. Он измеряет
скорость, проверяет память и сохраняет выбранные параметры вместе с результатом.

Проверка передачи параметров установленным OpenCode использует локальный
тестовый HTTP-сервер, без настоящей модели:

```sh
python -m tests.smoke_opencode
```

Проверка нового транспорта команд также использует установленный OpenCode
и подставной локальный API, без LM Studio и без рабочих задач:

```sh
python -m tests.smoke_process_tools
```

Сценарий создаёт временный проект и настоящий шлюз AgentVisor, обнаруживает
MCP-инструменты из запроса OpenCode и проверяет:

- отсутствие встроенного `bash` в инструментах модели;
- выполнение переменной PowerShell в Windows (Bash в Linux) без потери `$`;
- возврат `process_id` и опрос конечной команды до кода выхода 0;
- запуск принадлежащего сессии фонового Python HTTP-сервера;
- HTTP-проверку сервера отдельной командой;
- остановку сервера через `stop` и выход созданных процессов.

Для этого тестового запуска передаётся `--auto`; текущие настройки и задачи
пользователя не меняются. Сначала читается действующая политика OpenCode;
непереносимые ограничения останавливают тест, а не отключаются для него.
Срок процесса OpenCode ограничен 90 секундами;
после выхода закрываются шлюз, процессы и временный каталог. Успех подтверждает
совместимость установленного OpenCode с MCP и поведение транспорта. Подставная
модель выбирает команды по сценарию, поэтому этот тест не оценивает способность
реальной модели самостоятельно найти решение.

Для воспроизведения ручной выгрузки модели во время работы:

```sh
python -m tests.smoke_watchdog --model <идентификатор-модели> --context 65536
```

Запускайте её при отсутствии других активных задач на том же LM Studio.
Тест использует настоящий runtime и управляемый тестовый процесс вместо OpenCode:
выгружает свой экземпляр через API, ждёт watchdog, проверяет восстановление,
продолжение и сохранность ранее записанной работы отдельной командой.
Каталоги тестов и отчёты находятся в `.agentvisor-data/`; рабочие проекты
пользователя не используются. Разовый сбой и пауза отдельно покрыты pytest.

## Приёмка этапов и контрольные точки

Сквозная приёмка этапа без обращения к LM Studio:

```sh
python -m tests.smoke_step_review
```

Настоящий OpenCode работает в новой проверяющей сессии с локальным тестовым
ответчиком. Сценарий проверяет файл реальной командой, ждёт результат через
`wait_any`, записывает `STEP_REVIEW.json` штатным инструментом и проверяет,
что supervisor принимает этап по свежему событию успешной команды.
Старые отчёты, отсутствие доказательств, отмена, смена пользовательского контекста
и ошибки проверяющей сессии отдельно покрыты `test_step_acceptance.py`.
Снимки тестируются только во временных Git-проектах; индекс и рабочие изменения
сравниваются до и после. POSIX-права и недоступные Windows symlink могут давать skip.

## Проверка интерфейса

Откройте обзор, задачи, модели, историю и настройки. Проверьте переключение RU/EN,
сохранение введённых полей и выбранного языка после перезагрузки, переход из
события в журнал, клавиатурную навигацию и узкий экран.
Запустите демонстрацию: проверьте обновление плана, паузу, продолжение и итог.

В разделе **Модели** проверьте состояние сервиса, автозапуск в профиле,
сообщения установки и скачивания, выбор модели после скачивания, загрузку
и выгрузку из памяти. Остановка доступна только для своего headless-процесса;
при активной задаче или скачивании API должен отклонять её. Проверьте RU/EN
и сохранение введённых полей при переключении языка.

В отдельном тестовом каталоге данных проверьте **Настройки → Сетевой доступ**:
сохранение выбора при смене языка, скрытие/показ кода, сообщение об ожидающем
перезапуске и повторное подключение после применения адреса. С другого устройства
должен появиться вход по коду; ошибочный код не открывает панель. Возврат к
127.0.0.1 отключает сетевое подключение. Для Docker проверяйте публикацию порта
и AGENTVISOR_ALLOWED_HOSTS по инструкции в README.

Короткие автоматические и интеграционные проверки не подтверждают устойчивость
ночного запуска, восстановление после отключения питания или работу всех GPU.
Для длительной проверки используйте отдельную копию проекта, ограничьте время
задачи и задайте независимую команду проверки результата.
