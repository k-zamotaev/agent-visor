# AgentVisor

Локальная веб-панель для длинных задач OpenCode. AgentVisor запускает короткие
сессии, сохраняет состояние между ними, восстанавливает зависшие попытки и продолжает работу
после ошибок. Первая версия: Windows, Linux и Linux-контейнер Docker.

## Русский и English

Переключатель **Язык / Language** находится в верхней панели. Выбор сохраняется
в этом браузере; заполненные поля не сбрасываются при переключении.
Переводятся навигация, формы, статусы, ошибки API, подписи метрик и системный журнал,
включая старые события. Числа и время форматируются для выбранного языка.

Новая задача запоминает язык запуска: на нём сохраняются системные сообщения,
работает демонстрация и запрашиваются пояснения реального агента. Переключение
интерфейса не меняет язык уже созданной задачи. Ответы модели, вывод команд,
пути, названия задач и введённые пользователем тексты не переводятся автоматически.
Системные сообщения доступны на обоих языках без переписывания истории.

Use **Language → English** in the top bar. Your choice is saved in this browser.
New runs use that language for system logs and agent explanations; original model
and command output is preserved. API clients can send `Accept-Language: en`.
Подробности реализации: [docs/internationalization.md](docs/internationalization.md).

## Что работает

- Обзор: чек-лист, длительность, скорость сессии, восстановления, память и события.
- Создание задач, пауза, продолжение, остановка, изменение цели и лимитов.
- SQLite с историей; после аварийного перезапуска прерванная задача автоматически
  продолжается с диагностикой. Ручная пауза и остановка сохраняются.
- Новая сессия OpenCode на каждой итерации. `GOAL.md`, `PROGRESS.md`, `DONE.md`
  хранятся отдельно для каждой задачи.
- Таймаут завершает дерево процессов. Windows Job Object также убирает потомков
  при аварии supervisor; в Linux используются группы процессов и сверка PID при старте.
- Предел общего времени и итераций. Повторные ошибки и отсутствие завершённых
  шагов включают отдельную сессию ремонта с историей неудачных попыток.
- LM Studio: установка и запуск headless-сервиса `llmster` при необходимости,
  ожидание API, скачивание весов, загрузка и выгрузка моделей, проверка контекста.
- Ollama: загрузка установленной модели через API. Сервер запускается отдельно или Compose.
- Автопрофиль по памяти и короткому замеру скорости; ручные настройки контекста,
  рассуждения, выборки, GPU, Flash Attention и K/V-кэша.
- Наблюдение за моделью во время задачи и восстановление после выгрузки или
  отказа API. Отдельный таймер событий агента обнаруживает зависание даже при
  доступной модели; документы сохраняются между сессиями.
- Собственные инструменты выполнения команд: запуск, опрос и остановка процесса.
  Фоновые серверы не удерживают вызов инструмента, а ошибки сохраняются для следующих сессий.
- Проверка результата отдельной командой. Файл `DONE.md` сам по себе не означает успех.
- Демонстрация без модели и без доступа к вашему проекту.
- Переключение между localhost и доступом по сети из настроек; вход по коду
  с других устройств, сохранение режима и перезапуск панели.

## Автономное восстановление

Длинный запуск использует одну загруженную модель: исполнитель, диагност и
проверяющий работают последовательно. В журнале видны выбранная роль, режим
работы и результаты приёмки. Новые механизмы автономности:

- Обнаружение одинаковых причин ошибки при разных командах и смена стратегии.
- Постоянная память результатов, неудачных подходов и заметок `MEMORY.md`.
- Отдельная приёмка отмеченных этапов по свежим результатам инструментов.
- Диагностический проход с передачей конкретного ремонта исполнителю.
- `wait_any` для нескольких фоновых команд без повторного запуска.
- Контрольные точки исходников и отдельные копии для альтернативного решения.
- Библиотека проверенных команд проекта с подтверждением их происхождения.
- Адаптивные инструкции и предел ответа той же модели в рамках настроек пользователя.

Приёмка (`step_acceptance`), снимки (`checkpoints`) и адаптивный режим
(`adaptive_effort`) включены по умолчанию для рабочих задач. Последний также
уважает `auto_tune=false` и явный выбор reasoning. Снимки не сбрасывают исходную
папку или Git-индекс, а сценарии не дают новых разрешений. Проверяющий использует
ту же модель; отдельная итоговая команда проверки задачи остаётся полезной.
Ограничения и форматы описаны в [архитектуре](docs/architecture.md).

По умолчанию после 300 секунд без событий работы агента AgentVisor завершает
дерево зависшей сессии и запускает новую. Проверки доступности модели,
сообщения stderr и `step_start` сами по себе не продлевают этот интервал.
Таймер действует и при закрытых потоках вывода, если процесс не завершился.
Шлюз учитывает активность потока модели, включая reasoning. Для незавершённого
вызова инструмента действует отдельный срок: посторонняя генерация его не продлевает.

Новая сессия получает причину прерывания, текущий шаг, входные данные и ошибки
инструментов, хвост вывода независимой проверки и историю пяти последних попыток.
Сбой команды, проверки или CLI не вызывает перезагрузку исправной модели.
Модель перезагружается при отказе runtime/генерации или нехватке её памяти;
только для этих отказов пауза повторов растёт до 300 секунд. Для локальных
ошибок используется обычный `backoff_seconds`. При достижении `max_failures`
или `stall_limit` она переходит к устранению блокировщика: проверяет окружение,
выбирает другой способ выполнения и возвращается к исходной задаче.
Ошибочные итерации также учитываются; счётчики сохраняются после перезапуска.
Переписывание пояснений в плане без новых выполненных пунктов не сбрасывает их.
Неудачные команды отдельно сохраняются в SQLite вместе с оболочкой, каталогом,
выводом, кодом выхода и числом повторений. После двух одинаковых отказов повтор
требует изменить подход либо указать `repair_note` с конкретным исправлением.
Это защита от слепого повтора, а не доказательство правильности пояснения модели.

Параметры создания и изменения задачи через API: `idle_timeout_seconds`
(30–21600, по умолчанию 300) и `autonomous_recovery` (по умолчанию `true`,
включая старые задачи без этого поля). `false` возвращает остановку по локальным
лимитам повторов и паузу после аварии приложения. Общие `max_hours` и
`max_iterations`, ручные команды, проверки результата и ограничения проекта
действуют в обоих режимах. Восстановление не объявляет непроверенную работу
готовой и не гарантирует решение недоступных внешних зависимостей.

## Выполнение команд

OpenCode получает локальные MCP-инструменты `agentvisor_process_exec`,
`agentvisor_process_poll`, `agentvisor_process_wait_any` и `agentvisor_process_stop`, если существующие правила
OpenCode допускают безопасный перенос команд. Тогда встроенный `bash`
отключён через конфигурацию разрешений. В Windows команда по умолчанию
исполняется в PowerShell, в Linux — в Bash; оболочку можно указать явно.
PowerShell-код передаётся напрямую, без промежуточного раскрытия `$` в Bash.

`exec` возвращает `process_id`, состояние, код выхода и доступный вывод;
`running` требует последующего `poll`. Ожидание одного вызова ограничено
секундой, дополнительно может потребоваться время запуска и очистки процессов.
Для сервера используется `background=true` и прямая команда запуска, без
`nohup`, `&` или `Start-Process`. Готовность проверяется отдельной командой.
Повтор запуска той же ещё работающей команды возвращает существующий процесс.

Процессами владеет текущая сессия AgentVisor: таймаут, пауза, остановка и конец
итерации завершают их деревья, включая фоновые серверы. Это не механизм запуска
постоянных сервисов. Вывод хранится в отдельных `stdout.log`/`stderr.log` внутри
`<проект>/.agentvisor/tasks/<id>/commands/`; в ответ передаётся только хвост.
Пределы сессии — 16 активных и 128 созданных процессов. При достижении 8 МиБ
любым логом монитор останавливает процесс; между проверками возможен небольшой
выход за порог. Логи завершённых запусков автоматически не архивируются.

Перед подключением MCP проверяются действующие настройки проекта, общие настройки
и разрешения выбранного агента через OpenCode CLI. Простые списки запрещённых
команд сохраняются: PowerShell-код разбирается как данные, включая отдельные
команды после `;` и перевода строки. Динамические вызовы, перенаправление в другую
оболочку и непроверяемые аргументы запрещённой команды отклоняются. При
`external_directory=deny` собственный исполнитель недоступен: одного ограничения
рабочего каталога недостаточно, чтобы сохранить запреты на внешние пути в аргументах.
Это проверка команд, не изоляция ОС.
Неподдерживаемые правила или ошибка их чтения отключают собственный исполнитель,
сохраняя прежние инструменты и ограничения OpenCode; для ограниченного Bash
новый исполнитель требует использовать проверяемый PowerShell.

Вызовы MCP также проходят разрешения OpenCode. Настройка задачи `auto_permissions`
по-прежнему определяет передачу `--auto`; существующие запреты не снимаются.

## Скорость, рассуждения и дополнения контекста

В обзоре показаны две разные метрики. Средняя скорость сессии включает время
инструментов и ожидания. Скорость генерации показывает последний завершённый
ответ модели; переключатель над графиком выбирает одну из них. Во время ответа
отдельно виден статус генерации. Старые запуски не получают выдуманных измерений.

OpenCode обращается к своему локальному шлюзу на случайном loopback-порту с
индивидуальным адресом сессии. Шлюз передаёт запрос только в выбранный runtime,
наблюдает поток ответа и закрывается вместе с итерацией. При наличии метрики
runtime используется она; иначе `(completion_tokens - 1) / (время последнего
фрагмента - время первого фрагмента)`. Число токенов берётся из `usage`, а не
из числа сетевых фрагментов. Ожидание первого токена и инструменты исключены;
сетевая буферизация может влиять на замер. Без точного числа токенов или при
слишком коротком ответе новое значение не создаётся. Поддержка streaming usage:
[документация LM Studio](https://lmstudio.ai/docs/developer/api-changelog).

В журнале фильтр **Рассуждения модели** показывает реально переданный моделью
текст reasoning; модель может его не отдавать. Фрагменты сохраняются во время
потока, при этом вывод инструментов и ответы доступны отдельными фильтрами.
Поток токенов также поддерживает watchdog: активное рассуждение не считается
молчанием только потому, что CLI ещё не прислал завершённый ответ.

**Добавить контекст** в обзоре — необязательная подсказка без остановки задачи
и смены основной цели. Каждое дополнение сохраняется с номером версии и
передаётся при следующем запросе модели, в том числе внутри текущей итерации.
Дополнения остаются рядом с исходной целью в следующих запросах. Они не
добавляются повторно в конец диалога после результатов инструментов, поэтому
продолжение работы не превращается в очередное подтверждение той же подсказки.
Статус «передано модели» означает принятие запроса сервером, а не доказательство
выполнения указаний. Пока есть непереданные дополнения, задача не принимается
как завершённая. Лимит — 6000 символов на запись, 20000 символов и 40 записей
на задачу. API: `POST /api/tasks/{id}/context` с `{"text": "..."}`.

## Быстрый запуск на Windows

Нужен Python 3.10+; проверено на Python 3.12. Для реальных задач нужны OpenCode
и модель с инструментами. Локальный LM Studio AgentVisor подготовит сам;
для варианта с Ollama нужен работающий сервер Ollama.

Откройте **Start.cmd**. Он создаст `.venv`, установит Python-зависимости и откроет
браузер после готовности сервера. Повторный запуск открывает уже работающий
экземпляр с тем же каталогом данных, в том числе после обновления исходников.
В этом случае скрипт подскажет остановить прежний экземпляр через Ctrl+C
и запустить его заново, чтобы применить обновление.
Обычно адрес — `http://127.0.0.1:8420`; если порт занят, launcher выберет свободный
в диапазоне 8420–8440 и напечатает адрес.

Из PowerShell:

```powershell
python launch.py
```

Для английских сообщений запуска: `python launch.py --language en`.

Если OpenCode ещё не установлен, после установки Node.js выполните:

```powershell
npm install -g opencode-ai@1.18.4
```

В разделе **Модели** нажмите **Запустить сервис**. Если LM Studio CLI отсутствует,
AgentVisor установит `llmster` с официального сайта в каталог пользователя,
затем запустит headless-сервис и HTTP API. Окно LM Studio не требуется.
Первый запуск требует Интернета и может занять несколько минут.

Выберите установленную модель или откройте **Скачать новую модель**: укажите
идентификатор каталога LM Studio либо ссылку Hugging Face и, при необходимости,
квантизацию. Панель показывает состояние, объём и скорость скачивания.
После скачивания выберите модель, сохраните профиль и проверьте загрузку.
Для первого знакомства используйте **Задачи → Запустить демонстрацию**.

По умолчанию включено **Автоматически устанавливать и запускать локальный
LM Studio при необходимости**. Перед реальной задачей AgentVisor поднимает
сервис, дожидается API, выбирает установленную модель и загружает её с контекстом
из профиля. После отказа следующая попытка повторяет подготовку в пределах
бюджета задачи; при отключённом автовосстановлении действует также лимит ошибок.
В журнале видны этапы подготовки.

Существующий LM Studio используется повторно. **Выгрузить из памяти** освобождает
экземпляры выбранной модели, созданные AgentVisor (локально — `agentvisor-*`,
через REST — сохранённые идентификаторы). **Остановить свой сервис**
доступно для headless-процесса, запущенного AgentVisor; приложение LM Studio
и модели других приложений эта кнопка не завершает. При остановке панели
сервис остаётся доступным для следующего запуска.

## Linux без Docker

Установите Python с модулем `venv`, Node.js и OpenCode. Затем:

```sh
npm install -g opencode-ai@1.18.4
sh start.sh
```

LM Studio/llmster устанавливается и запускается автоматически, как на Windows.
Для официального установщика нужны `curl` или `wget`, `tar` и `libatomic`
(в Debian/Ubuntu — пакет `libatomic1`). Сервер Ollama устанавливается отдельно.
В среде без рабочего стола: `python3 launch.py --no-browser`.

## Открыть панель с другого устройства

При запуске через **Start.cmd**, **start.sh** или **launch.py**:

1. Откройте **Настройки → Сетевой доступ**.
2. Выберите **0.0.0.0 — все сетевые интерфейсы** и нажмите
   **Применить и перезапустить**. Если задача выполняется, сначала поставьте её
   на паузу. История, профиль и код доступа сохраняются.
3. На другом устройстве той же сети откройте показанный адрес компьютера,
   например `http://192.168.1.100:8420`, и введите код из настроек панели.

`0.0.0.0` означает прослушивание всех IPv4-интерфейсов; это не адрес для браузера.
На основном компьютере по-прежнему работает `http://127.0.0.1:<порт>`.
Если соединения нет, разрешите входящий TCP-порт панели в брандмауэре для
доверенной локальной сети. Само приложение правила брандмауэра не меняет.

Кнопка **Сохранить** оставляет смену режима до следующего перезапуска.
Чтобы отключить сетевой доступ, выберите **127.0.0.1 — только этот компьютер**
и примените настройку. Подключённые по сети браузеры потеряют связь с панелью.
Режим сохраняется в `network.json` в каталоге данных.

English: **Settings → Network access → 0.0.0.0 — all network interfaces →
Apply and restart**. Open the computer's network address on the other device
and enter the access code shown in Settings.

## Docker с автономным LM Studio

Скопируйте `.env.example` в `.env`, укажите существующий каталог проекта в
`AGENTVISOR_WORKSPACE`, затем:

```sh
docker compose up -d --build
```

Панель: `http://127.0.0.1:8420`. В задаче укажите **`/workspaces/project`**.
OpenCode, Python и Git уже входят в образ; Node.js нужен агентским инструментам.
Пакеты конкретного проекта при необходимости установите внутри контейнера.
В разделе **Модели** нажмите **Запустить сервис**, затем скачайте или выберите
модель. AgentVisor устанавливает и запускает headless LM Studio внутри контейнера;
приложение на хосте не требуется. Установка, движки и модели сохраняются в томе
`lmstudio-data`, история задач — в `agentvisor-data`. Порт модельного API наружу
не публикуется.

Для NVIDIA:

```sh
docker compose -f compose.yaml -f compose.lmstudio-gpu.yaml up -d --build
```

Нужны рабочие драйверы и поддержка GPU в Docker; на Linux — NVIDIA Container
Toolkit. Без GPU используется CPU. Системные драйверы AgentVisor не меняет.

При первом входе код доступа можно получить командой
`docker compose logs agentvisor`; затем он доступен в настройках панели.
В Docker вход по коду может требоваться и с основного компьютера: соединение
приходит через контейнерную сеть.

Для доступа из локальной сети задайте в `.env`:

```dotenv
AGENTVISOR_BIND_ADDRESS=0.0.0.0
AGENTVISOR_ALLOWED_HOSTS=192.168.1.100
```

Замените адрес на IP компьютера с Docker; дополнительные IP или имена можно
перечислить через запятую. Повторите `docker compose up -d` с теми же файлами
Compose. Внутри контейнера сервер всегда слушает `0.0.0.0`; публикацию порта
на хосте задаёт Docker. Поэтому переключатель адреса в веб-панели контейнера
заблокирован и объясняет, где изменить этот параметр.

Для уже работающего LM Studio на хосте задайте в `.env`
`AGENTVISOR_MODEL_URL=http://host.docker.internal:1234`; сервер должен принимать
соединения из Docker. Если включена аутентификация, задайте
`AGENTVISOR_MODEL_TOKEN`. Удалённый сервер запускается на своём узле;
AgentVisor управляет доступными через его API моделями.
Если профиль уже сохранялся, адрес в разделе **Модели** нужно изменить отдельно:
обновление `.env` не переписывает сохранённые настройки.

На Linux пользователь контейнера имеет UID 1000. Дайте этому пользователю права
записи в выбранный каталог проекта. Не монтируйте весь домашний каталог.

## Docker с Ollama

```sh
docker compose -f compose.yaml -f compose.ollama.yaml up -d --build
docker compose -f compose.yaml -f compose.ollama.yaml exec ollama ollama pull qwen3:8b
```

Первая команда запускает оба сервиса, вторая один раз скачивает выбранную модель.
`qwen3:8b` — пример модели с инструментами, не обещание лучшего качества.
Выберите её в панели. Скачивание больших весов запускается явным действием.

Для NVIDIA добавьте `-f compose.gpu.yaml` к первой команде. Требуются рабочие
GPU-драйверы и поддержка GPU в Docker; на Linux — NVIDIA Container Toolkit.
Сам AgentVisor не устанавливает и не меняет системные драйверы.

Для обновления: повторите `up -d --build`. Для остановки: `docker compose down`
с тем же набором файлов `-f`. Именованный том с историей сохраняется.
Смена Compose-профиля не переписывает сохранённые настройки модели — измените
сервер в разделе **Модели**, если этот том уже использовался.

## Создание задачи

1. Укажите существующий каталог и конкретный ожидаемый результат.
2. Задайте предел времени/итераций и при необходимости команду проверки.
3. Для автономной работы явно включите разрешение инструментов OpenCode.
   Агент получит возможность выполнять команды с правами процесса AgentVisor.
4. Создайте задачу и запустите. Одновременно выполняется одна задача.

Команда проверки задаётся как массив аргументов, без командной оболочки:

```json
["python", "-m", "pytest", "-q"]
```

Она запускается в каталоге проекта. Используйте исполняемый файл, доступный
AgentVisor; `.cmd`/`.bat` не исполняются как скрытая оболочка. Для npm-команд
на Windows можно вызвать Node и `npm-cli.js` явно.

Статусы результата:

| Статус | Что подтверждено |
|---|---|
| Завершена агентом | Актуальный DONE и все отметки плана; внешняя проверка не задана |
| Проверка пройдена | Дополнительно успешно завершилась заданная команда |
| Требует внимания | Исчерпан общий бюджет; при отключённом автовосстановлении также лимиты ошибок/прогресса |
| На паузе | Процесс остановлен; уже записанные документы и история сохранены |

Новая цель применяется со следующей итерации. Текущая сессия продолжает прежнюю
цель до завершения или паузы. Завершённая задача неизменна: создайте новую.
Пауза не отменяет уже записанные агентом изменения файлов.

## Модели и измерения

В разделе **Модели** выберите автоматический или ручной профиль. Автоматический
режим учитывает установленную модель, поддержку инструментов, предел контекста,
RAM/VRAM и оценку памяти runtime. Пустое поле модели разрешает выбор среди
установленных моделей; заполненное закрепляет выбранную модель.

Приоритет **Качество с контролем скорости** предпочитает большую модель и глубокое
рассуждение, затем проверяет заданную скорость. **Баланс** и **Скорость** уменьшают
начальный контекст, бюджет ответа и рассуждение. Число параметров модели служит
ориентиром ёмкости, а не доказательством качества её ответов.

**Предварительный подбор** показывает предложение без генерации. **Подобрать и
проверить** загружает и проверяет до четырёх вариантов коротким ответом, учитывает
остаток памяти и оставляет выбранный вариант загруженным. Результат калибровки
кэшируется на сутки для того же запроса, оборудования и списка моделей.
При запуске новой задачи эта проверка выполняется автоматически.

| Настройка | Как используется |
|---|---|
| Контекст и максимум ответа | Авто выбирает стартовый контекст до 65 536 для качества, до 32 768 для других приоритетов, с учётом предела модели; вручную значения задаёт пользователь |
| Размещение | Авто доверяет LM Studio; GPU/CPU можно задать явно для локального CLI |
| Flash Attention | Авто включает для локальных GGUF; при несовместимости пробует вариант без FA |
| K/V-кэш | Авто использует F16 или Q8 при нехватке VRAM; Q4 доступен только вручную |
| Рассуждение | Выбирается из возможностей, заявленных моделью, и передаётся в запрос OpenCode |
| Температура, Top P, Top K | Явные значения отправляются в API; пустые поля оставляют настройки сервера |

Flash Attention и K/V-кэш задаются через официальный LM Studio SDK. После загрузки
AgentVisor считывает фактические значения и отклоняет неподтверждённую настройку.
Квантование V-кэша требует Flash Attention. Оно экономит память, но может влиять
на точность; квантизация кэша и квантизация весов модели — разные настройки.
Оценка `lms --estimate-only` не принимает эти параметры, поэтому отмечена как
оценка с настройками runtime по умолчанию. Она не заменяет проверку загрузкой.
Ползунки открытого чата LM Studio не определяют параметры запросов OpenCode.

Подбор не доказывает глобальную оптимальность или качество решения вашей задачи.
Скорость короткого ответа отличается от скорости длинного агентского запроса.
Если цель скорости недостижима, панель показывает это и лучший измеренный вариант.
Сохранение профиля действует на новые задачи; существующие сохраняют свой профиль.
Старые профили без выбора режима сохраняют прежние значения контекста.

При переполнении контекста AgentVisor увеличивает окно. При нехватке памяти
уменьшает его, но не ниже уже обнаруженной потребности запроса. Если сочетание
не помещается, потребуется меньшая модель или другой профиль. Автовосстановление
сохраняет общий предел времени; без него также действует локальный лимит ошибок.
При перезагрузке локального LM Studio выгружаются только экземпляры с префиксом
`agentvisor-`, созданные приложением. Не запускайте несколько AgentVisor на одном
runtime одновременно: первая версия не координирует модель между экземплярами.

Во время агентской сессии watchdog проверяет API и конкретный экземпляр модели
примерно каждые 5 секунд. Два сбоя подряд завершают сессию, после чего контроллер
поднимает сервис и модель и продолжает со следующей попытки. Разовая ошибка
проверки не вызывает перезапуск. Пауза и остановка отключают наблюдение;
модель в это время намеренно не восстанавливается. Повторы ограничены настройками
задачи, чтобы неисправный runtime не перезапускался бесконечно.

Для удалённого сервера/LM Studio на хосте из Docker его оборудование не считается
известным. Панель показывает оборудование узла AgentVisor и предлагает небольшой
стартовый контекст без утверждения, что памяти сервера достаточно.
Настройки Flash Attention и K/V через SDK доступны для локального LM Studio,
включая llmster внутри Docker. Они не изменяют конфигурацию удалённого сервера
или Ollama. При использовании API-токена автоматическое изменение этих настроек
не выполняется: Python SDK этой версии не поддерживает такую аутентификацию.

«Средняя скорость сессии» = выходные токены / время агентских процессов, включая
инструменты и ожидание. Переключатель графика выбирает завершённые итерации либо
измерения генерации. Их история загружается отдельно от подробного журнала,
чтобы поток reasoning не вытеснял точки графика. Янтарная отметка объясняет
восстановление перед ближайшим измерением.

Короткий замер в разделе моделей отдельно показывает скорость всего запроса.
Для Ollama дополнительно доступна скорость генерации по `eval_duration`.
LM Studio через используемый OpenAI-compatible endpoint отдельную длительность
генерации не сообщает — панель её не выдумывает.

## Данные и ограничения первой версии

- Состояние: `.agentvisor-data/runtime/agentvisor.sqlite3`, либо `AGENTVISOR_DATA`.
- Документы: `<проект>/.agentvisor/tasks/<id>/`. Корневые документы проекта
  не перезаписываются.
- Журнал в панели ограничен последними 200 событиями. База хранит все события;
  автоматической архивации старых запусков пока нет.
- По умолчанию панель доступна только на localhost. Сетевой режим использует
  общий код доступа и предназначен для доверенной локальной сети; отдельных
  пользователей и ролей нет. HTTP не шифрует трафик, включая код доступа.
  Для доступа через Интернет нужны отдельные TLS и контроль доступа.
- Операция загрузки на удалённом runtime может закончиться уже после запроса паузы;
  новый агентский процесс после паузы не запускается.
- AMD/Apple GPU, разные квантизации, удалённый watchdog и многопользовательский
  сервер не откалиброваны. Очередь параллельных задач пока не реализована.
- Windows запрещает автоматический сон на время задачи. Linux/Docker не меняет
  политику сна хоста; для долгих запусков хост должен оставаться включённым.
- Короткие проверки не заменяют ночной прогон на вашем реальном проекте.

## Проверки разработчика

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
node tests/test_frontend_i18n.mjs
```

Опциональный реальный прогон создаёт отдельный тестовый каталог, включает
OpenCode `--auto` только для этого запуска и проверяет содержимое небольшого файла:

```sh
python -m tests.smoke_model --model qwen/qwen3.8-27b
```

Проверка настоящего OpenCode и новых MCP-инструментов без LM Studio:

```sh
python -m tests.smoke_process_tools
```

Она использует временный проект и подставной loopback API: проверяет переменные
оболочки, опрос команды, запуск HTTP-сервера, отдельный HTTP-запрос и остановку
сервера. Срок прогона OpenCode ограничен 90 секундами.

Инструкции по проверке — [docs/testing.md](docs/testing.md).
Архитектура — [docs/architecture.md](docs/architecture.md).
